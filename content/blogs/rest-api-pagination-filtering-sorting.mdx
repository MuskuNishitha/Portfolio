List endpoints start easy and become slow when the product grows. Search, filters, sort menus, and load more buttons all need backend support.

![REST API pagination illustration with pages, filters, and sorted records](/assets/blog/rest-api-pagination-filtering-sorting.svg "REST API pagination illustration with pages, filters, and sorted records")

## Where The Problem Starts

I make pagination explicit with page, limit, total, and hasMore or totalPages. The frontend should not guess whether more data exists.

## The Pattern I Use

Filters should map to indexed fields where possible. Sort options should be whitelisted so the API does not accept arbitrary database fields.

```js
const page = Math.max(Number(req.query.page) || 1, 1);
const limit = Math.min(Number(req.query.limit) || 12, 50);
const skip = (page - 1) * limit;

const [items, total] = await Promise.all([
  Product.find(filter).sort(sort).skip(skip).limit(limit).lean(),
  Product.countDocuments(filter),
]);
```

## Common Mistakes

- Returning every record and asking the frontend to filter.
- Allowing unlimited page sizes.
- Sorting by fields that do not have supporting indexes.
- Changing response metadata between endpoints.

## Production Notes

I test pagination with real data volume or seeded data. A query that feels instant with 20 documents can struggle with 20,000.
