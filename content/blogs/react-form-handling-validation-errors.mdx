Forms fail in more ways than empty required fields. The API can reject a value, the network can fail, a user can double submit, and a success message can disappear too quickly.

![React form validation illustration with input fields and API response states](/assets/blog/react-form-handling-validation-errors.svg "React form validation illustration with input fields and API response states")

## Where The Problem Starts

I separate client validation from API validation. Client validation catches obvious issues early, while API validation remains the final source of truth for uniqueness, permissions, and business rules.

## The Pattern I Use

A form component should know the current field values, touched fields, submit status, and server errors. When those states are explicit, the UI can show the right message in the right place.

```jsx
async function handleSubmit(event) {
  event.preventDefault();
  setStatus("submitting");

  const result = await saveContact(form);

  if (!result.ok) {
    setErrors(result.errors);
    setStatus("error");
    return;
  }

  setStatus("success");
}
```

## Common Mistakes

- Clearing all fields before the API confirms success.
- Showing backend errors only as a toast when the problem belongs to a field.
- Leaving the submit button enabled during an active request.
- Using placeholders as labels and making the form harder to scan.

## Production Notes

In production I also think about analytics and support. If many users hit the same validation error, the form copy or field design may be the real problem.
