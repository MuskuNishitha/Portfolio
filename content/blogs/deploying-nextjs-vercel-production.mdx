A Vercel deployment is smooth when the project is already honest locally. The production build, environment variables, images, and metadata should all work before pushing.

![Vercel deployment illustration with Next.js build and production domain](/assets/blog/deploying-nextjs-vercel-production.svg "Vercel deployment illustration with Next.js build and production domain")

## The Checklist

I run the build, confirm required variables, check dynamic routes, verify sitemap and robots, and open several pages after deploy.

## A Practical Pattern

For blog sites, I check that each article route is crawlable and that canonical URLs point to the production domain, not localhost or a preview URL.

```bash
npm run build
vercel pull --yes --environment=production
vercel build --prod
vercel deploy --prebuilt --prod
```

## Common Mistakes

- Assuming the dev server proves the production build will pass.
- Forgetting server-only environment variables in the Vercel dashboard.
- Testing only the home page after deploy.
- Leaving preview URLs in shared metadata or canonical links.

## Before Shipping

After deployment, I check the main pages, a few article pages, image loading, contact form behavior, and logs for route errors.
