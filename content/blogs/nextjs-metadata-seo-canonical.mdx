## Practical Code Examples

### Generate metadata from article data

This first example keeps the article grounded in Next.js metadata and canonical SEO pattern. It is intentionally small enough to paste into a project and adapt, but it shows the boundary that matters: unique titles, useful descriptions, canonical URLs, Open Graph images, Twitter cards, and Article JSON-LD.

```js
export async function generateMetadata({ params }) {
  const post = getBlogPostBySlug(params.slug);
  if (!post) return { title: "Article not found", robots: { index: false } };

  return {
    title: post.title,
    description: post.description,
    alternates: { canonical: "/blog/" + post.slug },
    openGraph: {
      type: "article",
      title: post.title,
      description: post.description,
      images: [{ url: post.image, alt: post.imageAlt }]
    }
  };
}
```

```js
export function absoluteUrl(path) {
  if (!path) return baseUrl;
  if (path.startsWith("http")) return path;
  return baseUrl + (path.startsWith("/") ? path : "/" + path);
}
```

## Common Mistakes

Most problems around Next.js Metadata For SEO, Canonicals, Open Graph, And Twitter are not caused by a lack of effort. They come from solving one visible issue while leaving the surrounding contract unclear.

- Fixing only the screen where duplicate titles, missing descriptions, broken OG images, non-canonical previews, and structured data that disagrees with the page appeared, while another route still uses the old pattern.
- Skipping the direct production-style check because the local development flow looked fine.
- Adding `use client` to a top-level route because one child uses a hook.
- Generating metadata from a different data source than the page content.
- Forgetting that image paths, content files, and environment variables must exist during production build.
- Testing only client-side navigation while direct visits to dynamic routes fail.
- Letting canonical URLs point to localhost, preview deployments, or mixed www/non-www domains.
