CORS errors look like frontend problems because the browser shows them, but the fix is usually in backend headers or deployment URLs.

![CORS debugging illustration with browser, frontend origin, and API server](/assets/blog/cors-production-api-debugging.svg "CORS debugging illustration with browser, frontend origin, and API server")

## Reproduce The Failure

I confirm the exact frontend origin, API URL, request method, credentials setting, and whether the browser is sending a preflight request.

## The Fix Pattern

Production CORS should allow known domains, not every origin. If cookies or auth headers are involved, credentials settings must match on both frontend and backend.

```js
const allowedOrigins = [
  "https://muskunishitha.vercel.app",
  "https://admin.example.com",
];

app.use(cors({
  origin(origin, callback) {
    if (!origin || allowedOrigins.includes(origin)) return callback(null, true);
    callback(new Error("Not allowed by CORS"));
  },
  credentials: true,
}));
```

## Mistakes That Hide The Real Bug

- Allowing localhost but forgetting the production domain.
- Using wildcard origins with credentials.
- Debugging the browser message without checking the network preflight response.
- Changing frontend API URLs without updating backend CORS.

## Production Debugging Notes

I keep allowed origins in environment configuration so staging and production can differ safely.
