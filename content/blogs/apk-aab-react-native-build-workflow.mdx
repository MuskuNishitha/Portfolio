APK and AAB files serve different release jobs. I use APKs for direct testing and AABs for Play Store upload when the release is ready.

![Android APK and AAB build workflow illustration with release artifacts](/assets/blog/apk-aab-react-native-build-workflow.svg "Android APK and AAB build workflow illustration with release artifacts")

## Where The Problem Starts

Before generating artifacts, I confirm environment values, app version, version code, signing configuration, icons, splash screen, permissions, and API endpoints.

## The Pattern I Use

The build workflow should be repeatable from a release branch. If a developer cannot rebuild the same artifact later, the process is too fragile.

```bash
cd android
./gradlew clean
./gradlew assembleRelease
./gradlew bundleRelease
```

## Common Mistakes

- Forgetting to increase versionCode before upload.
- Sharing keystore passwords in source control.
- Testing an APK built with staging configuration.
- Uploading without installing the release build on a real device.

## Production Notes

I keep a release checklist beside the app, not inside chat messages or memory. It saves time when updates become routine.
