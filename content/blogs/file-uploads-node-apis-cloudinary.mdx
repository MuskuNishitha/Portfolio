## Practical Code Examples

### Validate and persist Cloudinary uploads safely

This first example keeps the article grounded in Node.js file upload flow with Cloudinary. It is intentionally small enough to paste into a project and adapt, but it shows the boundary that matters: file type limits, upload streaming, Cloudinary public IDs, database consistency, and secure delete/replace behavior.

```js
const allowedTypes = new Set(["image/jpeg", "image/png", "image/webp"]);

export async function uploadProductImage(req, res, next) {
  if (!req.file || !allowedTypes.has(req.file.mimetype)) {
    return res.status(422).json({ errors: { image: "Upload a JPG, PNG, or WebP image." } });
  }

  const uploaded = await cloudinary.uploader.upload(req.file.path, {
    folder: "products",
    resource_type: "image"
  });

  res.json({ imageUrl: uploaded.secure_url, publicId: uploaded.public_id });
}
```

## Common Mistakes

Most problems around Planning File Uploads In Node.js APIs With Cloudinary are not caused by a lack of effort. They come from solving one visible issue while leaving the surrounding contract unclear.
