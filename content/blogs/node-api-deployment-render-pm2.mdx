Deploying a Node.js API is not only choosing a host. The app needs a reliable start command, environment values, database access, logs, and a way to restart safely.

![Node.js API deployment illustration with server process and logs](/assets/blog/node-api-deployment-render-pm2.svg "Node.js API deployment illustration with server process and logs")

## Define The Responsibility

Managed platforms such as Render simplify process management. VPS-style hosting often needs PM2 or a similar process manager to keep the app running after crashes or restarts.

## A Maintainable Shape

I add a health endpoint, set the production start command, confirm MongoDB connection, and check logs during the first deploy.

```bash
npm run build
pm2 start npm --name portfolio-api -- start
pm2 save
pm2 logs portfolio-api
```

## Common Architecture Mistakes

- Starting the dev command in production.
- Leaving required environment variables undefined.
- Running without process management on a VPS.
- Ignoring server timezone, port, and firewall behavior.

## Production Considerations

A backend deployment should be observable. If the frontend reports a 500, server logs should quickly show whether the issue is auth, database, validation, or a missing variable.
