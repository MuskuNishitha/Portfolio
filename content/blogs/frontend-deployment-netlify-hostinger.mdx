Frontend hosting problems usually come from build output, route handling, environment variables, or domain settings. The code may be fine while the host serves it incorrectly.

![Frontend hosting illustration with build output and domain configuration](/assets/blog/frontend-deployment-netlify-hostinger.svg "Frontend hosting illustration with build output and domain configuration")

## Where The Problem Starts

For React SPAs, the host needs fallback routing so refreshes on nested routes work. For Next.js, the hosting target must support the rendering features the app uses.

## The Pattern I Use

I write down the build command, output directory, Node version, environment variables, and domain records for each deployment. That prevents guessing during updates.

```bash
npm run build
vercel pull --yes --environment=production
vercel build --prod
vercel deploy --prebuilt --prod
```

## Common Mistakes

- Uploading source files instead of the production build output.
- Forgetting fallback rewrites for client-side routes.
- Using a host that cannot run required Next.js server features.
- Changing DNS and expecting it to update everywhere immediately.

## Production Notes

After deploy, I test direct refresh on nested routes, image loading, metadata previews, and API base URLs.
